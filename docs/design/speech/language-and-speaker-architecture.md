# 多语言与电话角色判断架构

状态：2026-10-30 的架构方案已用于 2026-10-31 实现；当前代码范围与实测限制见[实现记录](implementation-2026-10-31.md)，官方证据见 [能力核实](provider-capabilities.md)。

## 1. 产品目标

让用户能在中文、英语和已有文档依据的方言场景自然练习、作答，减少错误语言、错音色和把本人回答当作新问题的情况。保持 BYOK，不强制采购声纹云服务，不让业务界面到处判断厂商名称。

不设置“每轮确认是否采用参考答案”的步骤。真实面试继续默认沿用前文建议，明确实际回答与纠正优先。

## 2. 分开保存四种偏好

| 偏好 | 产品含义 | 例子 |
| --- | --- | --- |
| 识别输入 | 听懂用户和面试官说的内容 | 自动／中文／英语；方言标签作为能力匹配信息 |
| 答案输出 | 参考答案和问题正文使用的语言 | 跟随本轮问题／固定英语／固定中文 |
| 辅助显示 | 给用户阅读的翻译或解释 | 保留英文原文，下方显示中文辅助；默认关闭 |
| 面试官朗读 | 模拟面试 TTS 的语言、口音、音色和语速 | 英语＋英文音色；中文＋东北口音 |

应用界面语言不决定上述四项。不得把用户使用中文界面等同于需要中文 ASR 或中文朗读。

主语言与若干常用语言快捷项可以借鉴截图布局；“最多三种”作为首屏显示密度选择，不作为底层协议和数据结构的硬限制。识别自动模式不随每个短语频繁重连；需要固定输入语言的连接变更在句子定稿后有序切换。

### 真实面试

- 默认中文参考回答，允许选择跟随本轮问题。英文面试可固定英语，并可展开中文辅助。
- 保留识别原文，翻译存为派生内容；主答案、翻译、来源不能拼成一条不带身份的历史消息。
- 切换语言从下一轮生效；不清空会话、前文方案或资料快照。记录语言策略版本，避免晚到的旧翻译覆盖新设置。
- 专有名词、API、代码、复杂度和数字保持原意；不会因为换方言就替换关键技术约束。

### 模拟面试

- 分别设置问题语言、候选人输入模式、面试官口音、复盘语言。
- 普通话、英语、粤语可作明确的语言练习选项；四川、东北等默认作为表达/发音风格。重庆独立选项须标明官方通路和验证状态。
- 文本内容适合口头表达；需要粤语口语时由生成策略产出口语正文，TTS 负责声学表达。普通话文本套方言音色不必然得到地道方言。
- 难度与技术评分不因口音而扣分。除非用户开启语言练习，不把语法、口音或流利度当作技术能力。
- AI 出题和用户按键录音的归属已由流程确定，不必为模拟房间额外启动声纹识别。播放结束后再收音，用户开始作答时立即打断播报，避免回采。

## 3. Adapter＋策略＋能力注册表

沿用 `speechProtocol.ts`、`realtimeAsrProtocol.ts`、`ttsProtocol.ts` 的分层和既有 transport、超时、取消、密钥隔离，不引入一套平行网络框架。

| 模块 | 责任 | 不应承担 |
| --- | --- | --- |
| SpeechCapabilities | 描述服务、模型版本、协议、地域、voice 与可用功能的组合 | 根据厂商名称猜测所有模型能力 |
| AsrAdapter | 创建会话/提交片段，把供应商结果转为统一转写事件 | 把不存在的说话人结果补成确定身份 |
| TtsAdapter | 映射语言、voice、风格和格式，返回统一音频帧 | 负责问题生成、翻译或读取全局 UI 状态 |
| LanguagePolicy | 决定识别模式、问题/答案/辅助语言和方言表达 | 保存密钥或改变地域 |
| SpeakerResolver | 从音源、本人匹配与本场聚类证据决定角色 | 仅凭问句语气猜“这是面试官” |
| TurnRouter | 关联句子文本和角色证据；决定生成、记实答或等待 | 把识别完成直接等同于应该生成答案 |

推荐小接口，示意如下，不表示现有可调用 API：

```ts
interface SpeechCapabilityKey {
  providerKind: string;
  modelId: string;
  protocol: string;
  region: string;
  voiceId?: string;
}

interface SpeechEvidence {
  level: 'documented' | 'tested' | 'experimental' | 'unknown';
  checkedAt: string;
  sourceUrl?: string;
}

interface SpeechSegment {
  sessionId: string;
  captureEpoch: number;
  connectionEpoch: number;
  segmentId: string;
  revision: number;
  startMs: number;
  endMs?: number;
  text: string;
  textFinal: boolean;
  languageTag?: string;
  speaker?: {
    clusterId?: string;
    role: 'candidate' | 'interviewer' | 'unknown' | 'overlap';
    evidence: 'channel' | 'local-match' | 'provider' | 'manual';
    score?: number;
    final: boolean;
  };
}

interface SpeakerResolver {
  observe(audio: Float32Array, range: {startMs: number; endMs: number}): void;
  subscribe(callback: (event: SpeechSegment['speaker'] & {segmentId: string; revision: number}) => void): () => void;
  close(): Promise<void>;
}
```

采用工厂/注册表选择 Adapter，策略对象决定是否固定语言和怎样路由。无需实现庞大抽象父类；ASR 流式输入、文件 ASR、TTS 音频流保留各自接口。新厂商通常只增加 Adapter、能力条目与协议测试，业务 UI 不新增厂商分支。

能力使用组合规则而不是 `supportsDialect=true`：能识别方言、能朗读方言、支持语言提示、支持匿名 speaker、能匹配本人、支持 PCM 双工、只支持 SSE 输出，都分别表达。自定义网关不因 model ID 相同就自动获得官方地址的能力保证。

## 4. 手机外放场景的说话人流程

电脑麦克风收到混合音频。VAD 只判断是否有语音；音高、音量或男女声分类不能可靠代表身份。说话人分段、身份匹配和重叠声音分离是不同任务。

推荐先实现本机本人匹配＋会话说话人聚类：

1. 用户显式点击“校准我的声音”，在实际麦克风环境中录制若干段有效发言。界面给出音量、有效时长和背景串声提示。时长门槛通过候选模型实验确定，不照搬另一家云服务的数值。
2. Rust 本地提取 speaker embedding，形成本人模板。开始一通电话后创建独立的 speaker/role 映射；对方模板不跨场默认复用。
3. 音频正常转给现有 ASR；本地并行计算说话人证据。所有片段使用同一音频时钟与 segment ID 关联，不能只按两条回调抵达顺序配对。
4. 匹配本人且证据足够时记为候选人实答。非本人不能直接等同于面试官，还需本场聚类与角色绑定；可通过一次明确的对方发言校准，或用户单次标注 A/B 角色。
5. 明确归属的面试官发言进入问题装配；本人回答进入实际回答上下文，不再次触发“回答本人问题”的循环。
6. 太短、低信噪比、电视背景音、多人插话和重叠发言保留 unknown/overlap。先展示字幕，允许“回答这句”“这是我说的”或更正角色；不丢弃内容，也不把未匹配自动包装成确定身份。

这不是身份认证系统，不承诺零错误。本人声音跨语言、方言、感冒、距离和设备变化都需要验证。降噪不等于分离两个人的声音；若重叠率高，再评估专门的 segmentation/separation，不在第一版声称已经解决。

手机外放没有自动提供电脑端的干净远端参考音轨，不能仅打开现成回声消除开关就保证消除双方串声。电脑播放的模拟面试 TTS 则可由应用控制播放与采集生命周期。

## 5. 文本和说话人异步到达

维护每个 segment 的文本终态、speaker 终态与 actionRevision：

- 文本可以先显示，明确身份到达后再路由；等待不能阻塞 ASR 接收线程。
- 身份等待时间有上限，具体值需测延迟/错误触发曲线。到期保留可手动作答，不偷偷把 unknown 改为 interviewer。
- 角色后续更正时，取消相应旧生成，把产物标为旧归属并停止旧播放；不能删除观察记录或悄悄改写它。
- `captureEpoch / connectionEpoch / segmentId / revision` 共同防止重连后 speaker 编号复用、跨会话晚事件和重复答案。
- 仅凭第三方匿名 speaker 0/1 不推断候选人/面试官，角色映射是独立的会话状态。

用户仍可选择兼容的“全转写＋手动回答”模式；自动角色判断未校准不妨碍现有面试助手继续使用。

## 6. 播放、缓存和设置

- 全局 AI 服务保存连接和默认模型；具体会话保存语言/口音选择的版本快照，可局部覆盖。
- TTS 播放入口传入明确的 `SpeechRenderSpec`（语言、dialect/style、voice、语速、模型、地域），不能只依赖全局 `ttsVoice`。
- 缓存身份至少包括 provider/endpoint、model、voice、语言、风格、速率、文本与配置版本。改变任一项后停止旧播放并失效对应缓存，避免选择东北话却播出上轮英语缓存。
- 短句完整后即可合成播放，按顺序衔接；先播正文，辅助翻译默认不自动重复播报。用户关闭喇叭、开始录音、切换问题或结束会话都取消网络与音频队列。
- 未配置云 TTS 时枚举系统音色及语言，匹配后使用；未安装相应语音包时给出明确提示，文字功能继续可用。
- 方言音色缺失时提供用户可见的替代项：同厂商可用 voice、已配置的另一服务、普通话或文字。未获配置的服务不自动使用另一地域的 Key。
- 在“试听”前显示目标服务和音色；试听属于显式请求，不在打开设置时自动产生付费音频。

## 7. 本地说话人数据

优先把身份匹配留在本机 Rust 组件，采用官方维护的推理接口和独立模型资源。发布前固定版本、校验模型文件完整性，核实模型许可和 Windows/macOS 依赖。不能因为应用业务代码用 Rust 就声称底层库也都是纯 Rust。

默认只保留本场临时模板；长期保存本人模板需要明确开关、删除入口、存储说明与平台保护。原始录音不因开启角色区分而默认永久存档。远端识别需要哪些音频仍由所选 ASR 的现有数据发送范围决定，不额外发送本地 embedding。

若用户以后开通专用云声纹服务，通过独立配置与 Adapter 接入，不能冒用百炼普通 Key 或在后台创建云端声纹。
