# 多语言与电话角色实施路线

日期：2026-10-30。状态：**研究与设计已完成；下表功能尚未实施**。

本轮只新增本设计包与 ADR，不改变正在运行的应用、不重置设置、不录入或上传声纹。先交付语言与方言闭环，再引入需要真实音频验证的角色判断。

## 3. 接入顺序及扩展约束

第一条闭环选中文/英文切换：设置 → 会话快照 → ASR → 出题/回答 → TTS → 重播/打断 → 历史。第二条闭环选粤语；再扩展四川/东北等有文档依据的组合。重庆单独标记保证等级，不偷换成所有厂商都原生支持。

在现有模块里抽取小的 adapter 接口。首批分别登记 MiMo ASR（片段输入/SSE 输出）、百炼 Fun-ASR（持续 PCM/WS）、MiMo TTS、Qwen HTTP TTS、CosyVoice HTTP/WS 与系统 TTS。不把 `provider=mimo` 当作一个同时包办 ASR、TTS 和声纹的单体类。

后续增加厂商时必须补：

1. 明确协议和认证配置、模型/region 范围，不共享不兼容密钥。
2. 语言和方言请求映射；未支持参数不发送。
3. 文本/音频事件与终态映射，实际 speaker 字段有证据才消费。
4. 能力组合样本和测试，注册到统一入口；UI 不添加厂商判断。
5. 截断、拒绝、限流、超时、取消和晚到结果验证；沿用现有有限重试原则。

## 4. 角色判定试验

优先比较本地“本人匹配＋会话聚类”与现有“全转写＋人工选择”，不预设模型足够准确。保留语音片段时间轴、角色标签和误触发记录，人工标注是参考真值。

建议样本轴：

- 普通话、英文、粤语、四川/重庆口音、东北口音；同一人跨语言。
- 手机音量、电脑麦克风增益、30/80/150 cm 等距离，安静与生活噪声。距离是试验取样条件，不是产品保证范围。
- “嗯/好的”短句、长项目回答、双方抢话、电话回声、第三人插话。
- 用户打断 TTS、快速提交下一题、语言中途切换、设备拔插与网络重连。

记录：候选人误触发率、面试官漏答率、unknown 比例、角色修订次数、有效文本的 CER/WER、首个字幕/完整题目/答案的延迟、CPU/内存、真实费用。以场景结果决定阈值和等待时间，不能复制某个演示的 similarity 阈值当成跨模型标准。

## 5. 数据与兼容

- 新 SpeechProfile 有版本；旧 `interviewPreference.lang` 兼容读取并保留原值。未配置新资料时维持旧行为，不因升级自动改变回答语言。
- 每场快照保留初始策略，用户中途切换追加版本；不批量重写旧问答和 AI 来源。
- 明确保存 ASR 原文、可选翻译、角色证据和来源；speaker 推断置信度不是事实确认凭证。
- 多语种报错文本使用应用界面语言，模型问题/答案语言服从会话偏好。
- 模板、embedding、模型文件及普通音色缓存分目录管理；不把声纹文件放进自动导出的普通面试报告。
- 模型更新或设备校准变化可触发重新验证，不静默把旧模板套到不兼容的 embedding 模型上。

## 6. 研究证据与尚未覆盖范围

官方协议链接集中在 [能力核实](provider-capabilities.md)。本轮静态核实了现有代码入口、参数与文档；没有真实付费请求结果、方言试听盲评、本机 speaker 性能、macOS 原生音色测试或新增发布产物。
