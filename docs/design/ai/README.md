## 文档分工与状态

| 类型 | 保存什么 | 更新规则 |
| --- | --- | --- |
| audit | 某一读取版本的事实、发现、复现、限制 | 保留历史；发现变化时追加复核状态，不把旧事实改写成从未存在 |
| design | 当前推荐方案、接口合同、验收条件 | 说明变更缘由并关联迭代记录 |
| ADR | 有意义的长期取舍及替代方案 | 推翻时新增 ADR，旧记录标记 superseded |
| 实施路线 | 任务、依赖、证据、实际完成情况 | 没有实现和验证证据不得标记完成 |

最初三份架构 ADR 标为 `proposed`：表示推荐决策已写清、可供后续实现采用，**不表示完整目标架构已实施**。本轮新增 ADR 0004 记录用户明确补充的连续回答原则，基础实现及验证单独列示。它不额外引入人工审批步骤。后续落地后记录 commit / PR、验证范围及遗留问题，再更新实施状态。

## 本轮选择

1. 借鉴问题关联、显式纠错、合并与进度反馈；采用我们自己的稳定 ID、修订和本地状态规则。
2. 保持 BYOK 直连与本地会话编排；供应商差异藏在适配层，不要求用户搭自营服务端。
3. 先修来源真实性、上下文范围、完成状态和重试，再做提示词工作台、检索升级。
4. 短资料完整注入和改进词法检索先做对照；向量、重排和外部搜索是有门槛的可选能力。
5. 用任务数据和验收结果决定取舍，不用“原版有这个功能”或“使用了 RAG”代替质量证据。
