## 3. 每项任务的具体验收

### AI-001：先保证身份和来源不混淆

连续参考回答的默认采用行为见 [ADR 0004](../../adr/0004-answer-continuity-default.md)。这里的来源隔离不要求逐轮确认，也不阻止沿用已有答案。

交付：类型合同、兼容读取、保留来源的增量写入、迁移说明和备份恢复方案。

必须覆盖：

- 同一 role 在真实 / 模拟面试的不同含义不会被混用。
- AI 建议收藏到已有人工资料容器后，条目仍能知道来源不等于人工原创。
- 用户确认具体陈述不连带确认答案中的其他数字。
- 旧记录来源不能可靠判断时保留 unknown，不通过模型猜测。
- 迁移幂等；失败恢复；旧记录数量、原文、截图引用与时间不丢失。

不以“一次加两个 metadata 字段”作为完成标准。没有问题修订与旧结果关联规则时，来源字段不足以阻止晚响应覆盖。

### AI-002：把结束和正确分开

交付：供应商协议终态、任务产物状态、部分结果保存及重试分类；同步留下最小请求清单。

必须覆盖正常 stop、长度限制、拒绝、空响应、无终态 EOF、取消、schema 错误、已开始流式输出后的断线。unknown 不能伪造为 normal；有效片段不因终态失败丢失。

401 / 403、参数不支持不循环重试；429 / 暂时故障退避有次数、总时长与调用预算。上游是否已接受不明时，不承诺重试不会重复计费。

“已运行通过”必须引用实际验证记录；移除或准确改写没有评测依据的“目标通过率”功能。可选代码运行器不是此项前置条件。

### AI-003：让上下文跟随具体问题

交付：明确目标的纠错、合并、撤回、重试；按题目的 ContextAssembler 策略及可达交互。

关键验收案例：

1. 问题排队后被纠正，旧结果随后到达，不能覆盖新修订或播放旧语音。
2. 三个问题连续排队，处理第二题不将第三题误当作补充。
3. 第十题后追问第二题，保留第二题的原始约束、最新代码与必要图片。
4. 不同窗口对同一问题同时操作，预期版本失配可恢复，不靠最后写入静默获胜。
5. 合并 / 撤回保留历史关系，旧题不再占待答队列。
6. 一个 prompt 中当前问题只出现一次，相关的原始背景仍完整。

先人工可达和确定性规则，后评测自动语义合并；不要求每句话先走一次分类模型。

### AI-004：提示词和能力可解释

交付：旧模板注册为版本、任务参数和输出合同、按供应商适配的能力状态。

验收：同一输入版本可以重现请求装配；不支持的角色 / 参数不发送；未知能力不冒充已验证。正文、资料和快捷提示不得成为高优先级应用规则。

模型能力描述不出现在不认识这些字段的供应商请求中。变更连接地址或模型后，过期的能力证据不能继续作为确定结论。探测测试只能由明确动作启动，不在后台自动计费。

### AI-005：同一场训练看到同一份事实

交付：资料版本快照、动态片段选择、逐结果来源、题库 / 资料生成 / 提示 / 复盘共用事实入口。

验收：

- 短简历与 JD 的完整背景策略和检索策略可在相同样本上比较。
- 完全无命中的长资料可不返回；必要全局背景与检索命中分开记录。
- “那它为什么这么做”能借当前主题构造查询，不跨会话找错项目。
- 另一窗口编辑简历不会静默改写本场资料版本；主动刷新有新快照。
- 删除 / 撤销资料后停止新请求发送其正文；引用显示来源已不可用。
- AI 草稿不因匹配分数高而进入已确认个人事实。
- 题库与资料内出题不默认选第一份无关简历；无统计来源时不显示真实频率概率。

不要求此项引入 SQLite、embedding 或重排。质量收益与数据量决定是否进入 AI-009。

### AI-006：训练状态由程序掌控

交付：主题、配额、连续追问与总量规则；提示等级；带证据的复盘合同。

验收：无效 JSON 不被当作问题；模型连续建议 CONT 时仍受程序上限约束；比例设置语义与实际行为一致；不知道、改述、跳过和纠错有明确处理。

复盘能区别没问到、没听清和回答错误；点评引用实际消息；提示使用影响训练评价。报告不会把训练得分包装为录用概率。

### AI-007：质量结论必须可复核

交付：当前失败案例、任务样本格式、比较入口和去标识规则。先本地合成评测，真实模型按独立预算执行。

至少分四层证据：本地合同、协议夹具、合成交互、真实质量 / 实机。每次真实比较记录任务分布、样本数量、模型版本、重复次数、参数、成本与延迟；小样本不夸大为总体准确率。

检索、装配、提示和模型分别对照；记录开发集与留出集，自动评委需要人工校准。没有执行真实质量评测时不能因单元测试通过把任务标为 quality-evaluated。

### AI-008：开放自定义，但不暗改合同

交付：实际生效预览、风格参数、预设修订、恢复默认及有范围的专家编辑。

验收：修改只影响指定任务；旧占位字段不会升级后突然执行；预设更新不覆盖用户修订。自定义任务主体不能关闭来源、权限或终态校验。

AI assist 是主动调用、明确服务、结果为草稿；取消后不覆盖用户输入；“本地预览”不产生云调用。快捷提示绑定目标题目，不作为可执行模板脚本。

### AI-009：有收益才增加检索复杂度

触发条件：AI-005 的基线在真实任务上出现可复现的同义词 / 跨项目漏召回，或检索规模与延迟确需索引。

比较词法改进、短资料完整注入、混合检索及必要重排。采用前须说明正确性 / 召回增益和新增费用、等待、数据外发与维护代价。没有明确收益可以继续 deferred，不是必须实现的技术清单。

索引模型 / 维度 / 切块版本隔离，修改删除正确失效，断网有显式词法降级，Windows 与 macOS 的存储和构建经过验证。

### AI-010：语音标签必须反映证据

交付：采集源、预期 actor、说话人证据分离；原文 / 纠错保留；术语候选检查与适配。

验收：系统回采不天然等于面试官；真实面试中向助手的语音追问不变成候选人实答；未知身份有可操作的处理。未配置支持热词的协议不假装启用热词。

TTS 只播放当前有效问题；取消、更正、切题、退出、设备切换等场景分别测试。真实音质和 macOS 权限 / 音频设备效果需实机证据，不能只用模拟音频验收。

### AI-011：代码验证工具单独审视

当前保持 deferred。若实现，先明确用户主动启动、隔离、网络 / 文件权限、资源限制和结果证据，再允许执行来自模型或截图的代码。

运行样例、扩展用例和真实评测集的证据范围不同。即便该项未做，AI-002 的未验证标注与不伪造通过率仍必须完成。

### AI-012：诊断服务于解释，不能制造隐私副本

交付：不含密钥和默认正文的请求清单、有限健康提示与主动导出。

验收：能解释一次结果用了什么版本、为什么被标记不完整、发生几次调用；能指出无声或无命中，但不伪造质量分数。导出可脱敏、可清除；已撤销资料不为“重放”再次外发。

重放只承诺恢复装配条件，不承诺供应商返回完全相同文本。不要长期开启全量 prompt 日志来替代版本和来源清单。

## 4. 推荐推进顺序

1. 先用 AI-007 固定确定性失败样本与评测入口；建立 AI-001 最小身份模型。
2. 实现 AI-002 的结果、错误和取消合同，与最小诊断清单同行。
3. 用 AI-003 打通一条完整流程，再扩展到实时面试和模拟面试。
4. 用 AI-004 / AI-005 统一提示与事实入口，避免先做复杂指令工作台后再返工。
5. 落实 AI-006 的训练质量与 AI-010 的语音证据；持续做 AI-007 对照。
6. AI-008 作为用户可理解的产品界面；AI-009 / AI-011 在条件满足时另行进入。

这是依赖顺序，不是工期承诺，也不表示所有任务必须一起发布。每个迭代可交付一个能单独验证的纵向流程。

## 6. 防止再次把“原版行为”当作“正确答案”

每个新增需求先回答：它解决哪个本地问题？可观测证据是什么？BYOK 下由谁承担？怎样证明它有效？原版有什么并不构成必须加入的理由；本方案也不是不可推翻的标准答案。

若现有工作区修复已经解决部分审计项，先复核代码和验收证据，再更新任务状态，避免照历史行号重复实现。若选择与本设计不同，记录新证据和取舍即可，不需要为了“保持原设计”而保留已被证明更差的方案。
