# 分开判断供应商生成终态与任务产物完整性

BYOK 服务可能返回不同的结束标记、拒绝、长度限制和用量信息。推荐适配器报告供应商可证明的终态，任务运行时再检查结构与业务要求；传输 EOF、`[DONE]`、整段快照和有非空文本都不能独立证明答案完整或正确。

## 选择与替代方案

仅有字符串返回值易于接入，却丢失截断与未知终态；把某一家 API 的字段直接当成通用合同，又会误判其他兼容服务。选择“标准化结果 + 原始终态类别 + 适配器合同来源”，保留 unknown，不伪造 finish reason，也不要求用户的每个网关都支持严格 JSON。

能力信息保存在本地，由规划与适配器消费；客户端采集能力、自定义预算等字段不直接发送给模型。未知能力使用保守策略或由用户明确配置，探测需要显式动作并说明可能计费。

## 代价与约束

需要改造现有返回字符串的调用方，并为各供应商维护协议测试。长度截断须保留部分内容并标注；unknown 可展示但不伪装成已验证完成。即便供应商正常 stop、输出符合 schema，也仍可能答错，业务完整性校验与事实 / 代码验证分别记录。

重试是新的生成尝试，不承诺跨网络的 exactly-once 或零重复计费。输出后断线、取消与不确定的上游接受状态，不默认盲目重发；不能用无限重试隐藏兼容问题。
