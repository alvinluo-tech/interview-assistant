# 在本地编排 BYOK AI 任务，供应商差异由适配器承接

本产品已经采用用户自配模型和本地资料。推荐将问题、资料使用范围、提示装配与生成生命周期统一到本地任务运行时，由现有会话的拥有窗口运行；原生层负责跨窗口校验和可靠持久化，供应商适配器处理其实际协议。这样既保留 BYOK，也避免界面各自拼历史、猜模型能力。

状态 `proposed` 表示本次已形成推荐设计，尚未实现；不表示必须新增审批流程。

## 考虑过的方案

- 原版式必需自营服务端：有集中运营优势，但引入账号、运维、私密资料中转和新的费用主体，不符合当前产品约束。
- 每个页面独立直连：初期简单，但纠错、来源与完成状态会重复实现，难以保证一致。
- 通用多智能体平台：灵活，但当前主要任务可由有界工作流完成，额外调用和状态复杂度尚无收益证据。

## 结果与代价

选择本地编排并不意味着 UI 主线程承担所有计算，也不意味着所有任务都迁入 Rust。初期复用 TypeScript 装配与流处理，原生层做需要统一所有权的存储和校验；重索引可后移到本地后台。相同协议优先共用适配器，不为每个供应商名字新建一个透传层。

本地需要自行承担兼容性、诊断和质量验证；不能把原版服务端不可见当成这些责任不存在。后续若出现多设备持续后台任务或团队共享需求，可新增可选服务端 ADR，不强迫现有 BYOK 用户迁移。
