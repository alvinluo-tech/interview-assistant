# 默认连续沿用候选人可能采用的 AI 参考答案

用户明确补充：真实面试中候选人大概率直接采用或照读 AI 答案，答案质量和前后连贯性是核心要求。来源区分不能变成丢弃前文或要求反复确认。

决定：后续追问默认接续上一轮参考答案的架构、术语和前提；上下文保留前文建议。只有用户明确纠正、已记录的实际回答、资料事实冲突或发现技术错误时才更新前提。不要求每轮确认。真实面试与 AI 模拟面试的资料身份仍分开。

例如上一轮解释 Redis 缓存，下一轮问一致性，应继续说明该缓存方案的一致性取舍。若用户补充实际说的是本地缓存，则沿用实际说法。模型虚构的“延迟下降到 20 ms”仍不能自动成为个人事实，也不应在后续反复放大。

实现：`buildInterviewSystemPrompt`、`assembleInterviewHistory` 与可选的“补充我的实际回答”。问题识别错时可以更正并重答，旧版本保留但退出当前上下文。

验证：`tests/ai-optimization.test.mjs` 验证提示规则和上下文；`tests/interview-audio.test.mjs` 验证实际引擎连续回答与纠正；隔离界面检查验证更正与实际回答补充入口。它们验证客户端行为，不能证明所有供应商的答案语义质量。

替代方案：每轮询问是否采用会打断实时作答；完全过滤 AI 历史会造成追问换架构；无条件把 AI 建议当个人事实会放大编造。采用默认连续、显式纠偏、后台保留来源的方式。
