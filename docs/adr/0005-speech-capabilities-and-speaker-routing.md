# 用能力组合与独立说话人策略扩展语音服务

用户要求真实/模拟面试支持中文、英语与国内方言，MiMo 和百炼都能适配，并确认电话场景为手机外放、电脑麦克风采集。

推荐采用 Adapter＋策略＋能力注册表：语言偏好独立于界面语言，ASR/TTS 各自适配，能力定位到模型版本、协议、地域和音色。继续使用现有 transport、超时、取消和本地 BYOK 配置，业务 UI 不识别厂商私有字段。

说话人身份独立于 ASR：普通 Fun-ASR-Realtime 没有公开的说话人分离能力；MiMo 的多人转录能力也不能推导为提供身份标签。混合电话音频优先试验本地 Rust speaker embedding＋会话角色绑定，unknown 不等于面试官。提供可选人工纠正，不把每轮人工确认作为连续作答前置条件。

不选“按厂商写满 UI 分支”，因为同厂商不同模型和地域就已不兼容；不选“统一 language 参数”，因为单语提示、音色、风格指令和系统语音不是同一合同；不选“本人匹配失败就触发答题”，因为背景音、短句、重叠和设备差异会扩大误触发。

云声纹作为未来独立 Adapter。阿里现有专用服务有额外开通、地址和录入流程，不强制所有 BYOK 用户依赖它。TTS 声音复刻属于生成音色，不能替代对真实电话说话人的识别。

代价：需要维护能力证据、模型资源和设备评测；本地角色识别增加 CPU/内存与一定等待时间。它不能保证零串音，发布承诺以混合音频实测为准。

2026-10-31 接受并按此分层实现。Windows 原生与公开样本已验证，真实外放质量、付费试听和 macOS 真机仍需独立验收。详见[实现记录](../design/speech/implementation-2026-10-31.md)、[设计索引](../design/speech/README.md)与[原始实施路线](../design/speech/implementation-plan.md)。
