# 本地数据、截图和样例验证

## 数据

简历、资料、岗位、会话、题库和本地反馈仍保存在应用数据目录的 `data.json`。原生侧统一加锁，临时文件写入并同步后替换正式文件；成功后才更新界面与广播版本。不同窗口的不同记录/字段会合并，同一字段冲突会拒绝本次写入并提示刷新。

每次成功保存前保留 `data.previous.json`。在「设置 → 关于」可创建 `data.manual-backup.json` 并恢复它；恢复前的文件另存为 `data.before-restore.json`。这些文件包含简历与会话等个人资料，请按自己的隐私需求保管。备份不包含 AI 密钥，也不是跨设备云同步。

题库和收藏按岗位、简历与经验组合保存；本地反馈保存在独立的 `feedback` 集合，不再混入岗位。读取失败会阻止后续覆盖，写入失败不会显示保存成功。

## 更新

在「设置 → 关于」填写公开 GitHub 仓库 `owner/repo`。检查按钮查询 GitHub Release，比较版本并提供对应 Windows/macOS 安装包或发布页。网络失败、限流、仓库没有 Release 都显示真实原因，不再假定最新。

目前是检查并打开下载入口，需要手动安装；没有自动替换程序、签名校验更新或回滚更新机制。

## Windows 截图

笔试工作台可选择屏幕或前台窗口。默认尝试 GDI 屏幕截图；失败/空白时尝试 PrintWindow。兼容模式优先尝试前台窗口。前台窗口模式只读取前台窗口；请先把题目窗口放到前台。

纯色空白或黑屏会阻止发往 AI，并显示错误。部分受保护、硬件叠加或拒绝 PrintWindow 的窗口仍可能无法捕获；回退不保证所有应用可读。macOS 截图与系统收音尚需独立实现和真机验证。

## 代码样例

笔试工作台展开「代码样例验证」，载入最近答案中的代码或手动粘贴完整程序，填写标准输入与预期输出，点击运行。

需要本地 Docker 默认上下文中的 Linux 引擎，以及本地镜像 `python:3.13-alpine` 或 `node:22-alpine`。应用检查环境并提示缺失，不会自动拉取镜像，也不会回退到主机执行代码。可以自行准备：

```powershell
docker --context default pull python:3.13-alpine
docker --context default pull node:22-alpine
```

执行容器使用无网络、只读根文件系统、非 root 用户、禁用额外权限、无主机目录挂载，限时 10 秒、256MB 内存、半核 CPU、64 个进程和有限输出；结束/超时会清理容器。输出比较统一 CRLF 并忽略末尾空白。当前支持 Python 与 JavaScript 完整程序，核心函数需自己补输入输出包装。

当前机器 Docker CLI 存在，但 Desktop 启动后 Linux 引擎仍不可用，因此仅通过了参数约束测试和真实缺失环境提示检查，尚未完成实际容器执行验证。不能把模型解释样例当成真实执行通过。
