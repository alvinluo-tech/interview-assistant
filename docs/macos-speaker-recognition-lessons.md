# macOS 声纹与低音量语音输入：排查结论与经验

记录日期：2026-11-05。本文只记录本项目的排查与实现。

## 环境与现象

- 实机：Apple M2 MacBook Air，macOS 14.5，内置麦克风，48kHz 输入；应用重采样为 16kHz 单声道 PCM16。
- 电话面试等功能能够收音，但登记本人声纹反复提示“语音太轻或有削波”。
- 测试版录音统计：幅度超过 500 的采样比例约为 0.0%，削波比例为 0.0%，不同次录音峰值约 247–541（PCM16 满量程约 32768）。比例显示有四舍五入，0.0% 不代表完全静音。
- 系统输入音量从约 27% 调高到约 84% 后，登记仍失败；临时关闭降噪、自动增益也没有解决。测试后已恢复这两项设置。

## 确认的问题

声纹特征提取前，旧逻辑要求至少 5% 的采样点绝对幅度超过 500，否则直接拒绝。它把固定输入幅度当作可用人声的条件，并与削波共用一个错误提示。

这些低幅度录音会在进入 CAMPPlus 模型前被拦截。其他功能可以转写，不代表声纹专用的前置检查一定合理。不能据此认定麦克风损坏、权限失败，或确定 WebKit 对音频额外衰减。

## 当前修复

`src-tauri/src/speaker_audio.rs` 统一处理声纹注册和实时身份识别的音频：

1. 在增益前检查严重削波：绝对幅度超过 32700 的采样比例大于 5% 时拒绝。
2. 去除直流偏置，计算整段 RMS。
3. 按 RMS 计算增益，最多放大 32 倍，目标 RMS 约为满量程的 4%；峰值约束避免输出溢出。
4. 保留过弱信号检查（原始去偏置 RMS 小于 8）和归一化后的有效幅度比例检查。
5. 转换为浮点波形，再交给本地 CAMPPlus 模型提取并归一化声纹向量。

前后半段一致性、身份相似度与候选人/面试官的差值条件继续参与判断。增益处理不等同于人声检测，不能改善真实信噪比，也不能证明噪声一定会被排除。多人同时说话和极弱、嘈杂输入仍有限制。

## 实机验证与证据边界

- 修复后用户反馈：可以登记本人声纹；电话面试中自己的讲话能够识别为实际回答。
- 新增音量处理测试：幅度低于旧门槛的合成调制波形可通过；静音、恒定直流、极弱信号和严重削波被拒绝。合成波形测试验证预处理，不代表真实人声识别准确率。
- 前端构建、Mac 原生开发构建和音频回归测试通过。此机器旧 SDK 需要本地 apple-metal 兼容补丁和 Swift 链接路径；这些机器适配路径未写入项目配置。
- 未获得真实用户录音的声纹模型离线准确率评估；公开人声夹具下载超时。因此不能声称已验证跨设备、跨音量、噪声环境或所有说话人的识别准确率。
- 未进行 Windows 实机麦克风回归。预处理属于跨平台共享逻辑，Windows 也会使用。

## 临时测试包造成的独立问题

一次测试出现“当前环境无法访问麦克风”。临时应用包缺少正式项目已有的 `NSMicrophoneUsageDescription` 和音频输入 entitlement。补齐声明并重新签名、启动后，用户可以进入录音流程。

这与随后声纹的音量门槛失败属于不同阶段。开发测试包应继承 `src-tauri/Info.plist` 和 `src-tauri/Entitlements.plist`，并确认实际启动的包路径，避免同一 bundle identifier 的旧实例干扰测试。

重新签名测试包还可能触发系统钥匙串重新授权。一次启动停滞的线程采样显示，主线程正在通过 `SecItemCopyMatching` 读取本地配置密钥并等待安全服务响应。这类情况需要检查系统钥匙串弹窗，不能仅凭进程存在就认定主界面已经可用；需要用户自行完成系统授权，密码只输入系统弹窗。

## 后续复用的排查顺序

1. 先区分设备访问失败、无采样、采样过弱、服务返回空文本和身份不确定。
2. 用录音时长、峰值、RMS、削波比例和设备名定位；不要用“能听见”或“有权限”代替采样证据。
3. 比较正常功能与失败功能的不同处理分支，优先检查专用门槛。
4. 一次只改变一个条件。系统音量和预处理的试验没有改善时，不应继续认定它们是根因。
5. 注册和识别采用相同预处理；保留对静音、溢出、迟到结果和身份不确定的处理。
6. 不把相似度分数解释为正确率，不把构建通过解释为实机验证完成。
7. 诊断优先使用统计量；原始试音不因排查而落盘或上传。本人声纹默认在内存，用户选择记住后加密保存。

## 模拟面试的相关问题

2026-11-05 用户报告：实时字幕已经出现，再按空格结束时却提示“没听到你说话”。代码检查发现 `MockApp.tsx` 在调用实时 ASR 的 `finish()` 前，用 `voicedMs < 250` 或录音时长不足提前拒绝，并清空字幕。

当前修改让实时路径始终请求定稿，由最终文本判断有无识别结果；不把临时字幕直接当作最终回答。非实时文件转写保留原有录音门槛。

验证：从组件提取实际结束录音处理函数执行，旧实现无法通过“低音量已有字幕”和“短句实时定稿”两项回归；修复后通过。模拟面试、实时 ASR 和电话音频相关共 67 项测试通过，前端构建通过。用户完成系统钥匙串授权后，已在新测试版实测确认空格结束录音的问题解决，识别文字能够正常保留。
