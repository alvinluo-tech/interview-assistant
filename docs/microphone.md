# 模拟练习收音

「面试助手 → 模拟练习」使用麦克风，线上面试使用系统播放声音。

1. 在设置的 AI 服务中选择语音转写模型；启用自动回答时还要选择对话模型。接口需要支持 `/audio/transcriptions`，仅支持对话的模型不能转写。
2. 选择模拟练习后，可以选择输入设备并点击「测试麦克风」。检测仅在本机计算音量，不上传录音；开始练习、离开页面或停止检测时会释放检测设备。
3. 浮窗显示输入设备、音量条、正在收音的时长和转写状态。默认自动适配：MiMo-ASR 使用分段实时字幕，其他文件转写接口等待停顿后转写；也可在「设置 → AI 服务 → 请求与语音选项」选择输入模式。
4. 权限、设备断开及转写服务错误会直接显示，空白对话时也能看到。采集失败后点击「重试收音」。需要更换设备时结束练习，返回工作台选择设备。
5. 暂停会禁用麦克风轨道，丢弃未提交的片段并取消转写。结束或隐藏业务浮窗时释放设备，迟到的转写结果不会进入已结束的会话。

Windows 提示权限失败时，检查「设置 → 隐私和安全性 → 麦克风」中的麦克风访问和桌面应用访问。音量条长期不动时，检查系统输入设备和输入音量，或换一个麦克风。

如果未说话就出现固定问题，或无论说什么都得到相同文字，请先检查 AI 服务地址。`_recon/mock-ai.mjs` 是返回固定内容的开发夹具，不能用于真实转写。客户端会拒绝带测试标记的响应；测试脚本不得覆盖日常连接配置。自动分句还会过滤不足 250ms 的短促声音，避免单次碰麦或按键声触发转写。

开发验证：`pnpm test:audio` 覆盖 16k/44.1k/48k/96k 跨块重采样、暂停上下文恢复、权限/缺少转写模型、手动转写、暂停与结束取消、服务错误和重复启动。`scripts/audio-smoke.mjs` 使用隔离配置与本机测试服务验证桌面工作台和浮窗；不使用真实密钥或外部付费服务。

## MiMo 分段实时字幕与流式回答

MiMo `mimo-*-asr` 模型自动使用 `/chat/completions`，输入为 Base64 WAV 的 `input_audio` 消息，设置 `stream: true`，通过 SSE 增量更新字幕。其他模型继续使用 multipart `/audio/transcriptions`。两条协议共用现有连接、认证、超时、取消和错误脱敏。

采集期间约每 2.5 秒对新音频做一次预览，带 200ms 的边界重叠；单句最多一个预览请求在途，服务较慢时合并后续音频，避免积压。预览只显示临时字幕，不保存为问题，也不触发回答。停顿后取消过期预览，将整句重新识别校正，并只将最终文本提交一次。完整句子的识别结果和 AI 回答分别通过 SSE 更新。新的定稿问题会排队，避免上一题仍在回答时丢失下一题。

预览与整句校正会增加计费音频量，具体取决于语速、停顿、边界重叠和请求完成时间。可切换「停顿后整句识别」减少请求。纯静音不发送转写；暂停和结束会取消在途预览及未完成的整句识别。

这是基于文件接口的分段识别，不是持续上传 PCM 的原生 WebSocket ASR；约 2.5 秒是分段间隔，不包含网络和模型识别延迟。MiMo 官方协议：[语音识别 API](https://mimo.mi.com/docs/zh-CN/api/audio/Speech-Recognition)。
