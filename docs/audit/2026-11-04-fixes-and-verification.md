## 关键设计与使用注意

- **未保存答案仍在内存时不要退出应用。** 工作台可恢复尚未完成的笔试，恢复后可以重试结束/保存或复制答案。磁盘已经拒写时，程序无法保证强制退出或断电后保留尚未落盘的内容；此次修复解决的是错误发生时立即清空以及同进程恢复丢失尾部的问题。
- **设置失败不再假装生效。** 普通与严格设置均在成功后更新；已有调用者可以捕获拒绝，旧的忽略返回值调用也会收到可见错误通知。连续透明度等相对快捷键操作另行串行，保留每一步变化。
- **新数据校验不会“修好”损坏备份。** 显式错误结构、重复 ID、未来 schema 版本会被拒绝，原文件保持可供恢复。旧记录只是省略集合字段时可迁移；不会把一段错误内容直接清空来绕过检查。
- **分页保持内容来源。** 下一页条目使用 next_offset 或 next_cursor；单条长文本使用 entry_id 与 next_text_offset。AI 建议、未知来源与实际回答的语义不因续读而改变。

## 重跑

安装锁定依赖后执行：

```text
pnpm build
node --test tests/*.test.mjs
cargo test --locked --manifest-path src-tauri/Cargo.toml --workspace --lib
node scripts/audit/boundary-probes.mjs --verify
node scripts/audit/browser-boundaries.mjs --verify
node scripts/audit/run-browser-suites.mjs
node scripts/audit/native-boundaries.mjs --build --verify
node scripts/audit/protocol-fuzz.mjs
pnpm exec tauri build --debug --no-bundle
```

`--verify` 将仍出现的 finding 作为失败，不再以“取证完成”代替通过。结果使用 `fixed-` 前缀，与修复前证据区分。Node 业务回归已加入 `test:platform`，因此会随现有 CI 执行。浏览器和真实原生集成脚本仍需在对应运行环境显式执行；本次没有把需要 Windows Chrome 的脚本直接放进所有系统的 CI。
