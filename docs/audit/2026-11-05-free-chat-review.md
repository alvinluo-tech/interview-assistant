# 自由对话：本地资料授权与工具调用复核

日期：2026-11-05。范围：文字对话、语音通话、查询授权、工具协议、失败反馈与历史恢复。本轮未修改原生代码；本次交付用于拉取源码后进行 macOS 实机验证，不包含打标签或发布安装包。

## 结论

原有“默认关闭、本地只读工具、分页查询、来源标记”的方向合理，但执行边界和失败体验存在缺陷，不能据此宣称已达到最佳实践。本轮补齐类别授权、撤销、查询记录、协议校验及可重试的失败状态；继续使用现有 assistant-ui，无需更换整个聊天界面框架。

## 点击开关之后发生什么

1. 勾选只更新当前页面中该对话的授权状态；勾选动作本身不读取资料或调用模型。授权默认关闭，不写成永久全局设置。
2. 用户发送消息后，应用向配置的对话服务发送聊天上下文和四个工具的描述。此时没有自动附加全部简历、全部面试等资料。
3. 模型通过标准 `tool_calls` 返回工具名、参数和调用编号。应用只认可白名单工具，校验授权类别、参数、编号与数量。正文里的 DSML 标记绝不被当作可执行调用。
4. 应用在本机查询必要记录，返回有限的 JSON 结果。结果会作为工具消息发回同一个对话服务，供模型组织回答。资料是参考数据，不是新的系统指令。
5. 模型最终回答与不含资料正文的查询记录一起保存在本机；每条回答下可以展开查看本次查询记录。

授权期间可以继续多轮对话；切换到另一对话、离开页面后需要重新授权。结束语音通话回到同一对话时保留当前授权。改变范围或关闭开关会取消正在进行的请求。通话弹窗也提供“关闭资料查询并结束通话”。

**撤销不能撤回已经发出的数据。** 关闭开关后不再进行新的本地查询，但当前聊天历史中的既有内容仍可作为上下文发送。希望后续请求不携带这段历史，应新建对话。删除本机对话也不等于删除服务商已收到的数据。

## 工具与资料边界

| 工具 | 能做什么 | 限制 |
| --- | --- | --- |
| `app_guide` | 返回固定的功能与入口说明 | 不读取用户资料和密钥 |
| `list_local_data` | 列出选定类别的标题与有限摘要 | 每页最多 20 条，提供后续游标 |
| `search_local_knowledge` | 按关键词查找授权类别中的相关文字 | 2–80 字搜索词，最多 5 个有限摘录；不是全量语义检索 |
| `read_local_record` | 按 ID 读取选定记录的分页文字 | 简历/岗位/资料每页 6000 字符；面试每页 8 条、单条 3000 字符；笔试每页 5 题、题干/答案分别最多 3000 字符 |

五类资料分别可选：简历、岗位、面试资料、面试记录、笔试记录。工具定义中的类别枚举和实际执行器均限制到已授权类别，搜索也执行同一限制。

工具不能任意读取磁盘文件，不能读取截图附件、系统文件或 AI 密钥设置，也不能修改或删除资料。来源不明的旧资料保持 `legacy_unknown`；AI 参考答案不等于用户实际回答。资料管理中的正文和条目现在均可分页读取，面试文字也加入关键词搜索。

## 已确认并处理的问题

| 问题 | 修复与验证 |
| --- | --- |
| DSML 中插入空格后漏过识别，普通对话流与旧记录也缺少保护 | 统一识别半角/全角管道、空格和未完成的 DSML 头；流式片段合并判断；旧记录仅在显示时替换为说明，不批量改写或删除用户历史 |
| 失败被当作成功结束，出现连续用户气泡却无回答 | 使用 assistant-ui 的失败状态；在对应消息显示原因与重试按钮；失败记录可恢复，重试不新增同一个用户问题 |
| 失败/中断的回答被重新当作正常历史依据 | 保存完成状态；后续请求排除不完整的助手回答与协议泄漏内容；保留用户消息 |
| 请求取消之后仍可显示迟到回答 | 每个响应、工具读取、工具回传和输出边界检查取消/授权；离开对话会取消当前工作 |
| 查询中开关被禁用，无法直接撤销 | 允许查询期间关闭；变更类别也会取消旧请求；语音弹窗有单独撤销入口 |
| 只有一个广泛的授权开关 | 增加五类资料的范围选择，说明接收服务、只读范围及历史上下文边界 |
| 查询记录只有模糊的工具名称 | 每条回答保存工具、类别、记录 ID/标题、数量与成功/失败/缓存状态；不在查询记录里重复保存资料正文 |
| 重复工具调用编号未提前拒绝 | 整批验证编号与调用结构，出现同批重复编号时不执行任何工具 |
| 非数组或空的工具调用可被误当作成功回答 | 校验 `tool_calls` 容器与 `finish_reason` 的一致性，错误明确显示并可重试 |
| 查询同一页直到耗尽轮数 | 本轮结果缓存，按解析后的参数去重；一整轮没有新结果时进入无工具总结，不继续循环 |
| 本地查询的文字输出未设置上限 | 应用模型输出预算，默认文字 4096 token、语音最多 700；工具定义也计入输入预算 |
| 多轮工具结果缺少总量边界 | 保留单批 16、每次用户请求最多 24 个调用的限制；最多 5 次带工具的模型请求；新结果累计最多 60000 字符，达到边界后仅根据已有结果总结 |
| 资料能列清单但无法读详情，搜索遗漏面试 | 增加面试资料详情分页，搜索覆盖已授权的面试文字，保留各条来源标记 |
| 无工具总结可能使用期间更改的服务配置 | 总结前核对服务与模型身份，配置已更改则终止，避免把已查询资料自动发送给新服务 |
| 语音失败后缺少持久提示；通话重建丢失授权 | 保存语音失败状态，回到文字界面可重试；授权由当前对话的上层管理 |
| 生成中仍能开启语音输入，录音/转写时 Enter 可提前发送 | 生成中禁止开启手动录音；录音和转写期间拦截直接发送，仍可编辑草稿 |
| 导入历史中的可选查询元数据格式异常可导致渲染错误 | 读取时校验并限制查询记录字段与数量，忽略异常项；不因此删除原始聊天记录 |

## 仍需认识的边界

- 工具格式取决于实际模型及其网关是否支持。应用会拒绝错误协议并给出重试/更换模型提示，不能从正文中猜测工具指令后执行。
- 本轮授权粒度是资料类别；尚未实现逐条勾选简历/面试或每次发送前预览正文。类别授权仍可能覆盖同类下的多个人物或岗位资料；最终回答应明确引用范围，身份冲突需要核实。
- 最近三场是默认查询建议，配合硬性调用/数据量限制；并非强制只有三条记录，也不代表自动覆盖全部历史。
- 关键词搜索有数量上限；复杂问题应结合清单与详情分页，不能把“搜索未命中”解释为整个资料库不存在相关信息。
- 默认不保留跨轮的原始工具结果缓存；本轮缓存减少重复读取，下一轮按需重新查询，避免删除/修改资料后继续使用旧正文。历史回答仍可能包含之前已读取的信息。
- 查询记录标记的是执行情况，不保证模型每一句结论都正确引用证据；应结合实际回答、参考建议和缺失证据判断。

设计依据：[OpenAI Function calling](https://developers.openai.com/api/docs/guides/function-calling) 的结构化调用、参数校验和工具结果回传流程；[assistant-ui LocalRuntime](https://www.assistant-ui.com/docs/runtimes/custom/local-runtime) 的取消与消息状态机制。不同兼容服务对严格 Schema 支持不同，因此本轮保留兼容的工具定义并在应用执行层强制校验，不统一强开 `strict: true`。
