## 3. 本轮确认的遗漏/潜在缺陷

### R01 · P2 · 普通业务 Dialog 没有复用语音弹窗的焦点约束

- 位置：`src/ui/primitives.tsx:156` 的 `Dialog`，实际使用于资料管理的“新建岗位”等表单。
- 当前 `useModalFocus` 只接入了 `VoiceCallDialog`。普通 `Dialog` 仍只是遮罩与 Escape 处理，没有焦点循环、背景不可交互处理或完整的 dialog 语义。
- 本轮浏览器复现：打开“新建岗位”，从岗位输入框连续按 Tab，焦点到达弹窗外的 BODY；原弹窗保持打开。
- 影响：键盘可以离开当前模态表单，有机会操作背景内容。这是实际使用流程中的同类遗漏；此前 F03 的验收只覆盖语音弹窗，不能扩展为“所有弹窗都已修复”。
- 建议：让普通 Dialog 统一接入模态焦点管理，并同时处理嵌套弹窗的层级、Escape 和焦点恢复，不能只给所有 Dialog 各自注册一套互相争抢的全局监听器。

### R02 · P3/潜在 · useClickOutside 延迟订阅与卸载存在时序缺口

- 位置：`src/ui/primitives.tsx:374`。
- 真实 Hook 先安排 `setTimeout(...addEventListener...)`，清理时只执行 `removeEventListener`，没有取消还未执行的定时器。
- 最小复现：运行 effect → 卸载清理 → 执行先前定时器，最终剩余 1 个 mousedown 监听器。
- **影响边界**：搜索当前整个 `src` 仅找到定义，没有调用点。因此只能确认辅助 Hook 的潜在清理缺陷，不能宣称当前页面已因此持续泄漏、卡顿或堆积录音。
- 建议：删除未使用的辅助函数，或在清理时同时取消定时器并移除监听器，再补快速挂载/卸载回归。

## 4. 综合报告中需要纠正或补证据的内容

1. **F02 的代码与解释矛盾。** 它展示了 `if(saved) setState(...)`，却说无论 saved 是否成功都会清空；本轮保留/重试探针直接证明当前没有该行为。
2. **F04 的示例不能支持其注释。** `setText(prevText => ...)` 是基于最新 state 的函数式更新，本身不等同于旧闭包问题；其方案 A 在 await 前捕获 `currentText`，仍可能过期。当前实际修复在转写返回时读取最新 composer。
3. **F09 的示例并非当前实现。** 例子中的 fetchConfig、5 秒 setTimeout 和 `_serverVersion` 不是本地配置读取的现有合同。请求在返回后才分配序号，无法证明请求发起顺序，不能直接照抄该建议。
4. **多段代码是示意代码。** 报告使用的 `updateInterviewSession`、`search_local_knowledge()` 独立函数、`SettingMap` 等，不等同于当前仓库实现；定位应以实际源码为准。
5. **“HTML/JavaScript 未经过滤”证据不足。** 本轮 B07 仍验证了 Markdown HTML 没有生成可执行元素、注入没有运行；代码使用 React 文本节点，手机页也有 `esc()`。这只反驳“一律未经处理”的概括，不构成整个应用不存在 XSS 的保证。
6. **12 个 Medium 与 8 个 Low 没有清单。** 没有逐项位置、触发条件和复现证据，无法判断是否独立、重复、已修复或只是建议。不能直接增加 20 个待修复 bug。
7. **约 95% 不能作为全应用覆盖率。** 所列覆盖率来自指定模块的各套门禁，套件还存在重叠。当前最近全量 Node 验收为 293 通过，报告里的 284 是修复前数字。
8. **编号与版本对象需修正。** 深层 Markdown 项重复写作 F11，正确是 F12；业务 `data.json` 已有 schema v1，AI 配置已有 version 2。“整个 store.json 统一版本迁移”仍可作为架构建议，不能等同于 F13 尚未修复。
9. **62/100 和“两周迭代”不是当前验收结论。** 未提供适用于修复后代码的重新评分依据或工作量拆解，不能沿用为现在的评分与工期。
