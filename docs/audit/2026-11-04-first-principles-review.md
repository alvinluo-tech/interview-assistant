## 3. 已复现问题

P1：正常功能的异常分支可导致内容丢失、无法使用或关键业务误判，应优先修复。P2：特定并发、容量或输入边界下功能不完整、误报成功或需要重载恢复。

### F01 · P1 · 首次启动保存示例数据失败，会停在空白窗口

- **证据**：浏览器探针 `B09`，执行真实 `src/main.tsx`。合成存储返回正常空数据，首次写入抛出磁盘错误后，`#root` 子节点为 0，页面正文为空，产生未处理的 Promise 拒绝。
- **位置**：`src/main.tsx:23–34`、`src/lib/backend.ts:451`。
- **根因**：初始化依赖全部成功之后才创建 React 根节点；`ensureDefaultData()` 失败没有顶层恢复处理。React 错误边界此时尚未挂载，无法兜底。
- **影响**：首次运行、数据目录只读或空间不足时，用户看不到设置、错误说明和重试入口。
- **修复与验收**：先挂载启动/恢复界面；初始化 Promise 捕获错误并可重试。注入读取失败、示例写入失败、事件订阅失败时，窗口均必须显示明确原因及可操作恢复入口。

### F02 · P1 · 笔试结束时保存失败，仍清空唯一的内存答案

- **证据**：探针 `A01`。生成流已在内存追加“仅存在内存中的尾部”，磁盘只有先前空答案；结束时拒写。函数抛出错误，但最终 `remainingTurns=0`、`remainingSession=null`。
- **位置**：`src/lib/examEngine.ts:563–577`。
- **根因**：无论 `persistTurns()` 是否成功，`finally` 都重置会话 ID、题目和状态。释放收音/浮窗资源与销毁待保存内容被绑在同一个步骤。
- **影响**：最近一次检查点之后的答案可能永久丢失。此前检查点成功并不能保护尚未落盘的尾部。
- **修复与验收**：始终释放设备与浮窗，但保留未保存快照和会话归属；提供重试保存或导出。模拟检查点成功、尾部更新、结束拒写的完整顺序，恢复磁盘后必须能保存完整尾部。

### F03 · P1 · 语音通话弹窗可通过 Tab 逃逸，并开启第二路录音

- **证据**：浏览器探针 `B03/B04`。从通话结束按钮按 Tab 后焦点离开弹窗；继续用 Tab 到背景“语音输入”按钮并按空格，真实 React 处理器使 `activeMicrophones=2`。结束通话后本轮测试最终释放为 0。
- **位置**：`src/main/sections/FreeChatPage.tsx:122–150`、`173–193`。
- **根因**：`aria-modal` 只描述语义，代码没有建立焦点循环或让背景进入不可交互状态；手动语音输入也没有与通话共用互斥门禁。
- **影响**：两路采集同时存在，可能重复转写、增加回声或争用输入，绕开“通话中暂停其他输入”的视觉预期。
- **修复与验收**：弹窗管理焦点、背景 `inert`，并在业务层对通话/手动输入建立统一互斥；不能只靠遮罩。覆盖 Tab、Shift+Tab、空格、快捷键、快速开始/结束和启动尚未完成的情况。

### F04 · P1 · 转写返回会覆盖用户在等待期间的新草稿

- **证据**：浏览器探针 `B05`。录音前输入“初始草稿”，等待识别时改为“等待识别时的新编辑”，随后返回转写；最终内容为“初始草稿 识别出来的文字”，新编辑消失。
- **位置**：`src/main/sections/FreeChatPage.tsx:173–181`。
- **根因**：异步回调使用录音停止时捕获的 `composer.value`，而不是识别完成时的最新草稿；等待期间输入框保持可编辑。
- **修复与验收**：保留用户最新编辑，或将转写作为可选择插入的独立片段；明确草稿版本。覆盖输入、清空、粘贴、切换会话和取消后迟到转写，不得恢复旧草稿或覆盖新文字。

### F05 · P1 · 资料搜索工具会丢失 AI 生成来源标记

- **证据**：探针 `A04`。原条目 `origin=model_generated`，内容为第一人称项目成果；`search_local_knowledge` 返回值只有 `source` 和 `excerpt`，没有来源标记或非个人事实说明。
- **位置**：`src/lib/freeChat.ts:59–68`。对照同文件 `read_local_record` 及 `src/lib/knowledgeContext.ts`，其他读取路径已经具备来源信息。
- **根因**：搜索流程重新拼装资料与问答文本时，没有传播条目级 `origin`。来源不变量没有跨所有工具统一实施。
- **影响**：综合分析时，模型拿到第一人称参考答案，却不知道它由 AI 生成，可能把建议误读为真实经历。系统提示不能恢复已经被删除的来源信息。
- **修复与验收**：每个摘录附带来源、记录/条目 ID、位置和截断信息；未知旧来源也明确标记。通过所有工具读取同一条 AI 建议与实答，来源含义必须一致。

### F06 · P2 · 修改已删除会话会返回成功，实际没有保存任何内容

- **证据**：探针 `A11`。分别更新不存在的面试和笔试 ID，两次均未拒绝，最终两个记录列表仍为空。
- **位置**：`src/lib/backend.ts:265–274`、`328–337`。
- **根因**：通过 `map` 更新记录，没有检查目标是否存在，也没有返回受影响记录数。持久化空列表成功被当作业务更新成功。
- **影响**：另一个窗口删除记录后，迟到生成或结束操作可能显示保存成功，但新内容根本没有归属。
- **修复与验收**：显式返回 `not_found/deleted`；调用者保留未保存内容并提示恢复路径。不要静默重新创建用户已删除的记录。覆盖删除与请求完成、重试、结束的交错顺序。

### F07 · P2 · 普通设置写入失败，仍更新缓存并广播新值

- **证据**：探针 `A02`。`store.save()` 抛出只读错误，调用没有拒绝，缓存已改变，跨窗口成功广播计数为 1，实际持久写入失败。
- **位置**：`src/lib/store.ts:49–70`。
- **根因**：默认分支先乐观更新，在持久化失败时只输出日志，仍继续发送变更事件；`strict` 仅保护部分调用。
- **影响**：本次会话看似设置成功，重启后回退；多个窗口都可能展示未落盘的值。
- **修复与验收**：区分暂存状态和已持久化状态；失败回滚或清晰显示未保存，并支持重试。磁盘拒写时不能广播“已保存”含义的事件。

### F08 · P2 · 设置首次加载失败后，同进程无法重新加载

- **证据**：探针 `A03`。连续两次 `hydrateStore()`，实际加载只尝试 1 次。
- **位置**：`src/lib/store.ts:22–44`。
- **根因**：`hydrating=true` 在失败后没有恢复；拒绝的 `storePromise` 也一直被缓存。只重置其中一项不能完整修复。
- **影响**：临时文件锁、权限修复后，当前进程仍保留默认或不完整设置，只能重启。
- **修复与验收**：失败时解除初始化占有并清理失败 Promise；区分正在加载、已加载与失败。第一次拒绝、第二次成功时必须重新读取真实值并通知所有订阅者。

### F09 · P2 · AI 配置加载乱序时，旧响应覆盖新配置

- **证据**：探针 `A07`。并发触发两次真实 `reloadAiSettings()` 逻辑，先完成新配置、后完成旧配置，最终状态为 `revision=old`。
- **位置**：`src/lib/aiSettings.ts:16–29`。
- **根因**：没有请求代次、单飞合并或配置版本判断。
- **影响**：多窗口保存/刷新与事件交错时，模型路由、语音模式或凭证视图可能短暂回退到旧值。
- **修复与验收**：只允许最新有效代次更新配置和错误状态；串行读写或比较服务端版本。测试旧成功晚于新成功、旧错误晚于新成功，以及保存和刷新交错。

### F10 · P2 · 超过 3,000 字的单条问答尾部无法通过工具续读

- **证据**：探针 `A05`。返回 `truncated=true`、文本 3,000 字、`next_offset=null`，尾部关键证据缺失。
- **位置**：`src/lib/freeChat.ts:49–55`。
- **根因**：分页单位是消息/题目条数，而单条内容内部又单独截断；没有条目内字符偏移。笔试长答案也使用相同截断模式。
- **影响**：助手能知道内容缺失，却没有工具补取完整代码、答案或论证，综合分析覆盖范围受限。
- **修复与验收**：提供记录内条目 ID 和字符游标，或按块分页；显式返回下一块。将关键证据放在第 3,001 字之后，必须能逐页完整读到。

### F11 · P2 · 本地记录清单超过 20 条，没有下一页接口

- **证据**：探针 `A06`。25 条简历只返回 20 条，`has_more=true`，传入 `offset=20` 被拒绝。
- **位置**：`src/lib/freeChat.ts:13–16`、`26–27`、`70–77`。
- **根因**：清单声明还有更多记录，但工具参数不支持游标/分页；记录详情又依赖先获得 ID。
- **影响**：仅靠清单无法发现更早的记录。搜索在部分内容上可能提供绕行，但不等同于完整清单，也不能保证发现空正文记录或精确 ID。
- **修复与验收**：增加稳定排序和分页游标，输出下一页；覆盖 0、20、21、100 条及分页期间新增/删除记录。

### F12 · P2 · 深层 Markdown 引用会导致渲染栈溢出

- **证据**：浏览器探针 `B08`，输入 3,500 个连续 `>` 加文本。触发 `Maximum call stack`，正常视图被真实 `ErrorBoundary` 的“重新加载”界面替代。
- **位置**：`src/overlay/Md.tsx:8–64`。
- **根因**：引用块通过 `renderBlocks()` 递归处理，没有深度、节点数或复杂度预算。输入本身只有几千字符，单靠总字数限制无法防御。
- **影响**：异常模型响应或粘贴内容可以中断整个当前窗口；若异常内容已经保存，重新进入该记录还可能再次触发。
- **修复与验收**：限制递归深度/总节点数，超限部分降级为纯文本，隔离单条消息渲染错误。覆盖极深引用、超宽表格、海量行和未闭合代码围栏。

### F13 · P2 · 原生存储接收结构已损坏的嵌套业务记录

- **证据**：真实 Windows 原生探针 `N06`。`messages="not-an-array"` 的面试记录被成功提交并读回，`rejected=false`、持久化类型为 `string`。
- **位置**：`src-tauri/src/data_store.rs:223–235`。
- **根因**：原生边界校验集合类型和顶层 ID，未校验会话 `messages`、笔试 `questions`、资料 `entries` 等必要嵌套结构；读取/恢复也没有完整业务 schema 迁移检查。
- **影响**：结构异常的旧数据、人工编辑或合法 JSON 损坏可进入核心存储；多个 UI/工具假设这些字段是数组，存在后续渲染或查询失败风险。本轮确认的是“异常结构可入库”，不将所有消费者的崩溃都算作已复现。
- **修复与验收**：引入版本化业务 schema 和受控迁移；拒绝覆盖异常数据，保留原文件并提供可恢复错误。覆盖缺字段、null、错误类型、重复子 ID、异常状态及备份恢复。

### F14 · P2 · 岗位保存失败时，没有向用户显示失败原因

- **证据**：浏览器探针 `B11`。填写新岗位后令磁盘提交失败，产生未处理 Promise 拒绝；没有保存失败提示，岗位数保持 1，弹窗内草稿仍保留。作为对照，正常岗位创建、真实 PDF 导入、题库生成/收藏/存入资料流程均通过。
- **位置**：`src/main/sections/ResourcePage.tsx` 的 `GoalDialog` 保存按钮，直接 `await saveGoal(...)` 后关闭弹窗。
- **根因**：按钮异步处理没有错误捕获与保存状态。底层抛错被全局日志记录，但没有转成当前表单可理解的错误反馈。
- **影响**：用户点击保存后没有结果，也不知道是权限、空间还是保存冲突；草稿尚在，不应把它描述为已经丢失。
- **修复与验收**：表单统一显示保存中、成功和失败，失败保留输入并可重试；补查同页其他写入按钮的错误反馈。连续点击、拒写、冲突、恢复后重试都应得到明确结果，不出现未处理拒绝。

## 5. 安全与架构风险：不要混同为已经利用成功的漏洞

1. **手机传输未加密：已确认设计现状。** 令牌对错误连接的拒绝已在真实程序验证，但配对页面和 WebSocket 使用 HTTP/WS。令牌认证不能防止能够观察该网络流量的一方读取传输内容。可信家庭局域网与公共/公司网络的风险不同；本报告不把它写成“任何同 Wi-Fi 的人都能直接控制”。建议按数据敏感性推进 HTTPS/WSS 或明确限制与告知。
2. **局域网连接资源边界：代码审查风险。** `src-tauri/src/dual_screen.rs` 的监听器对每个连接创建线程，HTTP 请求头采用单次读取超时，尚无明确的全局并发上限与整体握手期限。消息/帧已经限制为 64KB。未执行大规模连接攻击，不能宣称已复现服务耗尽；建议补并发连接配额和总握手截止时间。
3. **CSP 和权限面较宽：加固项。** Tauri 配置的 CSP 为空，HTTP 支持自定义服务地址。浏览器中的 HTML/`javascript:` 注入测试没有执行脚本，不代表所有 UI/依赖均通过 XSS 审计。建议建立最小可行 CSP，并审查远程内容与自定义协议边界；不能将“未发现脚本执行”升级为安全认证。
4. **密钥保护已有直接正证据。** 合成密钥通过真实 Windows 加密存储往返，磁盘未出现该明文；更新签名与版本绑定测试通过。这不覆盖恶意本机管理员、进程内存读取、依赖供应链或用户手动配置外部 HTTP 服务的风险。
5. **测试不能替代依赖漏洞情报。** 本轮未上传仓库到第三方扫描平台，未执行外部依赖漏洞数据库扫描，也未审查完整 Git 历史。当前受控源码的轻量密钥模式检查没有命中；这不能证明所有历史提交及所有形式的秘密均不存在。
6. **覆盖率与 CI 存在层级差。** 现有 CI 会执行多套单元/协议/库测试及平台编译；本轮独立浏览器审查探针尚未成为 CI 门禁。即便本报告所列覆盖率门禁通过，新发现的问题仍能成立。新探针应在修复后转成有正确断言的回归测试，而不是把 `finding` 退出 0 接入 CI 后误称“已拦截问题”。

## 6. 建议修复顺序与验收门槛

### 第一批：阻止丢内容和不可使用

F01、F02、F03、F04、F05。对应设计调整为：启动先有恢复界面；结束时先确保数据可恢复再销毁状态；所有录音统一拥有权；草稿使用版本感知合并；所有工具统一返回来源证据。

验收要求：上述最小复现不再出现，同时在失败后能够重新操作。仅修复正常路径或把输入禁用而未说明原因，不算通过。手机/浮窗/设备释放不能因为保存失败而被阻断。

### 第二批：统一持久化与读取合同

F06–F11、F13、F14。统一 `not_found/conflict/not_saved` 错误及表单反馈；加载使用请求代次；分页应覆盖每条记录的全部内容；schema 和迁移共同保护记录边界。

### 第三批：隔离恶意或异常内容的破坏范围

F12，以及连接资源限制、CSP 和手机传输改进。渲染单条异常消息应降级该条内容，不能迫使整个窗口重载。

### 发版前仍需的真机验收

- Windows：真实麦克风、系统回采、蓝牙断开/重连、默认输出变化、睡眠/唤醒、长通话、真实第三方会议软件和双显示器 DPI。
- macOS Intel/Apple Silicon：首次授权、拒绝/撤销授权、多个 Space、第三方应用原生全屏、锁屏/睡眠、浮窗恢复、真实更新替换与重启。
- 安装与更新：干净安装、旧版覆盖、用户取消、锁定进程、低磁盘空间、升级失败恢复、卸载后保留/移除资料的实际行为。
- 网络：真实手机热点/家庭 Wi-Fi、短断网、长断网、手机后台、VPN 切换、限流，以及可达更新源。不要用本机合成服务器的时延代表国内用户的联网体验。
- 本地代码执行：准备本地 Linux 容器引擎与既有镜像后，再运行正常输出、无限循环、过量输出和内存压力；本轮没有自动拉取镜像。
