## 提交与发版判断

没有先把待复核版本发布给用户。先创建本地基线提交 `3608211`（安装器蓝白设计、语音播放及原始审计资料），基线构建和 170 项 Node 测试通过，再逐组增加失败用例、修复并提交。后续检查点保留在当前 main 分支，未推送、未创建版本 tag。

建议先让修复版本通过 Windows/macOS 两种架构的 CI，再发布下一个补丁版。Windows 本地检查不能替代 macOS 编译、签名及真实设备验收。版本继续由 tag 驱动，不手改 0.1.0 源版本，也不覆盖 v0.1.3 的既有安装包。
