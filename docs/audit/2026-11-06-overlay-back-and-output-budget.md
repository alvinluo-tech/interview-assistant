# 面试浮窗返回对话、输出预算与中断恢复修复

日期：2026-11-06。发布状态以版本标签和发布流水线为准。

## 现象

1. 面试中截图答题后，点击答题页的「返回对话」没有反应，只能结束会话。
2. 面试作答偶发「回答因输出长度限制被截断」；有时正文为空，只剩错误提示。
3. 收音或网络出错一次后，整场面试停在「出错」，后续转写与作答都不再继续。
4. 单个面试回答经常太长，现场念不完。

## 根因

### 返回对话

浮窗默认处于穿透模式（`interview.interactive` 默认 false → `set_ignore_cursor_events(true)`），原生窗口不接收鼠标事件。穿透模式下只有注册为热区、由 `cursor-zone` 轮询驱动驻留触发的 `DwellButton` / `DwellIconButton` 能响应用户操作。

`SolverView` 内容区和 `SolverActions` 底栏的「返回对话」都是普通 `<button onClick>`，既没有 `registerZone`，也没有悬停触发，所以在穿透模式点击无效。此前 `scripts/experience-ui-smoke.mjs` 的「返回对话」断言运行在主窗口仿真容器（`interactive=true`）里，没有覆盖穿透路径，因此没有暴露该问题。

### 输出长度

DeepSeek V4 官方文档（Chat Completions）：`thinking` 省略时默认开启思考；`max_tokens` 是本次生成的总 token 上限；`completion_tokens_details.reasoning_tokens` 单独统计思考用量。旧实现给 `interview-answer` 的上限只有 1800，复杂问题会把预算全部消耗在思维链上，以 `finish_reason=length` 结束，正文可能为空。

解析器此前只累计 `content`，完全忽略 `reasoning_content`，因此无法区分「思考吃满预算」和「正文写到一半被截断」，两种情况都只能显示同一句「已保留生成内容」。

### 中断后不恢复

`reportInterviewError` 会把引擎置为 `status='error'`。而 `scheduleGateCheck`、`flushUtterance`、`drainAnswers` 都只在 `listening` / `answering` 下工作，所以一次收音或转写失败就会让整场面试停摆，必须手动点「重试收音」。

更糟的是转写队列的 `.catch` 也调用了 `reportInterviewError`：一次保存失败（磁盘、IPC）同样把状态打成 `error`，连正在工作的收音也一起作废。同时，上一题的 AI 请求如果卡在 90 秒超时里，后面排队的题目一直等它，面试官已经问到下一题了还在补上一题。

### 回答过长

系统提示词只要求「默认 1–3 段、约 150 字」，对现场口述来说仍偏长，模型容易展开成小作文；回答上限调高后更需要提示词约束长度。

### 穿透模式没有操作提示

穿透模式下窗口不接收鼠标事件，所有操作都靠「悬停驻留」触发，但界面上只有一圈很淡的描边：拖动把手没有任何文字说明，用户不知道要悬停多久才能抓住浮窗，也不知道抓住后静止多久会放下；顶部还有一个「笔试答题」图标，和截图入口重复。

## 修复

- 答题页内容区新增 `DwellButton inline`「返回对话」，底栏新增 `DwellIconButton` 返回按钮；两者都注册热区，穿透模式悬停 1.1 秒、窗口模式直接点击都可用。头部「笔试答题」入口保持只进入不切换，避免同一热区在答题页反复触发来回跳转；顶部右上角因此只保留穿透切换、一键配色、结束三个入口，截图答题仍从底部「截图提问」或快捷键进入。
- 穿透模式悬停提示：控件带 `data-dwell-ms` 时，平台层在控件旁弹出提示气泡，显示「{名称} · 悬停 {n} 秒」并画一条与真实驻留时长同步的进度条；拖动把手的名称是「抓住浮窗」（悬停 0.9 秒），进入拖动后气泡切换为「移动鼠标定位 · 静止 0.8 秒放下」。提示不接收鼠标事件，不遮挡操作。
- 输出预算：`interview-answer` 1800 → 8192，`mock-question` 768 → 4096，`mock-hint` 1024 → 4096，语音对话 700 → 2048（`exam-solve` / `exam-followup` 维持 8192）。模型拒绝过大上限时（HTTP 400 且消息提到 `max_tokens`）自动降一档重试一次，避免小上限模型整轮失败。
- 解析 `reasoning_content` / `reasoning` 与 `completion_tokens_details.reasoning_tokens`：思考内容不计入正文，只在请求轨迹里记录，生成信息显示「思考 N tokens」。
- 截断不再标记为 AI 掉线，也不再套用「AI 作答失败」；正文为空且确有思考内容时提示「思考过程占满了输出预算，没有生成正文；可以直接重试。」回答成功后清空旧提示。
- 中断自动恢复：收音/网络类失败后按 2s、4s、8s、16s、30s 退避自动重连，成功即清零；最多连续 10 次，之后保留手动「重试收音」。用户暂停、结束、切换会话都会取消待执行的恢复。转写队列里的保存失败只提示、不再把整场置为 `error`。连接层失败（断网、代理抖动、证书握手）在面试作答里自动重试一次。实时语音发送积压超过两秒时改为丢弃过期音频并重连实时连接（不再整场停止收音），重连失败才交由引擎恢复。
- 面试节奏：新问题到达时，若上一题回答已卡住超过 25 秒，直接中止旧回答让新问题接管。
- 回答长度：自然口语改为「默认 2–4 句、约 100 字，只有明确要求展开时才补充」，并新增现场口述规则「30 秒内说完、一次只给一个方案、不复述问题、不写标题和表格」。结构化风格总长从 250 字收紧到 200 字。

## 全面审计后的修复（同日第二轮）

审计发现的问题按 P1 → P2 顺序修复，均已通过类型检查、构建与回归测试：

- P1 预览真实操作：`SimulatedPlatform` 下所有驻留按钮与结束按钮只展示不执行，避免预览里真的截屏、建记录、调 AI。
- P1 幽灵热区：zones 上报前与滚动容器、窗口视口求交（`visibleRect`），滚出视区的控件不再在别的应用位置形成热区。
- P1 答题页滚动：SolverView 补上上下边缘滚动 pill，穿透模式也能滚动长答案。
- P1 持久化失败隔离：转写保存失败不再阻断自动作答；回答已生成后保存失败只提示「暂未保存」，不再被标成 AI 失败或产生未处理拒绝。
- P1 无会话死按钮：抽出 `bootInterviewSession`，「重试收音」在无会话时补建会话。
- P1 截断标记：25 秒接管与手动打断都写入 `completionStatus:'cancelled'`。
- P1 迁移失败：损坏/超限的旧 `data.json` 改名保留，不再阻塞读取与「恢复手动备份」。
- P1 AI 设置解密失败：新增 `cmd_ai_reset_settings` 与「清除无法读取的配置」按钮。
- P2：补齐 `interview.microphoneId` / `mock.assistMode` 设置键；示例数据只预置一次且只在主窗口；清理示例数据改用 `isSample` 标记；挂载浮窗移动/缩放/透明度/配色热键并绑定语音提问；窗口模式拖动位置持久化；结束/恢复清理 `answerPending` 与队列；队列条目未被消费时放回队首；权限/组件版本错误不再自动重试；语气词只删除独立成词的位置；删除笔试记录时回收截图附件；`data.previous.json` 最多 30 秒刷新一次；恢复前快照按时间戳轮换保留 3 份；启动时备份 `store.json`；WDA 绕过只在调试构建生效；看门狗触发时把用户带回工作台；悬停提示随滚动更新；拖动把手同一次悬停只触发一次；隐藏浮窗的空闲重载加 `sessionStorage` 闩锁。
- AI 层：自由对话截断时保留已生成正文；上下文预算先扣输出与提示余量再分配；TTS 兼容接口逐段请求；工具调用非法时优先用已取资料作答；思考输出也视为已产生输出（不重复计费重试）；429 不再自动重试；调用方 `maxTokens` 受任务上限约束。
- 实时语音：重连窗口内 `finish()` 不再发 finish-task；连接稳定 10 秒即重置重试预算；排空与定稿共用一个 8 秒预算且不重复发 finish-task；取消时定稿以 AbortError 结束；手动语音输入发现丢帧会提示重试；麦克风事件在启动窗口内也能被捕获。
- 数据写回：`useData` 的 setter 支持函数式更新，记录页/进度卡的删除与改结果基于写入瞬间的最新缓存，避免旧渲染快照覆盖其他窗口的新数据。
- 穿透模式折叠区：回答下方的「生成信息」「本轮参考资料」以及上方的「本次回答参考 N 段」原本是原生 `<details>`，穿透模式收不到鼠标事件因此永远打不开；统一改为 `DwellDisclosure`（悬停即展开，窗口模式也可点击），每条消息使用独立 zone id。
- 结束面试后回不到主窗口：`cmd_show_main` 原来先 `reapply` 反录制/伪装、失败就 `?` 直接返回，`show()` 根本执行不到，前端 `.catch` 又把错误吞掉；且 `show()` 不保证抢到前台。现在加固步骤只记日志，`show/unminimize` 必定执行，并补了 Win32 置顶再取消置顶 + `SetForegroundWindow` 的前台提升，失败也会写日志。
- 结束面试的窗口切换不再依赖收尾：`endInterview` 最多等 6 秒，超时照样切窗口（写盘在后台继续）；顺序改成「先亮主窗口、再收浮窗」，主窗口没起来就保留浮窗并提示重点一次，避免两个窗口都不可见。
- `endInterview` 改为单飞：用户点「结束面试」与浮窗被收起后的兜底清理不会再各跑一遍停麦/写记录/完成会话。
- 只读审计（2026-11-07）后的修复：短句定稿不再只挂在 `partial` 上（`pendingShort` 独立持有，下一句定稿/暂停/结束前先补交）；正式结束排在临时收尾之后时不再被吞掉 `complete`（补写 `completeSession`）；标记「面试官」时若已有回答在跑，问题回到 `answerQueue` 而不是静默丢弃；系统收音在 `startSystemAudioCapture` 返回后发现代次已变，会自己 `stopSystemAudioCapture` 收掉；回答完成不再无条件清 `errorMessage`（保留收音/转写错误原因）；麦克风启动即断开/静音时直接失败，不再返回「看着在录」的句柄；流式期间不再每个 token 复制一遍 `turns`；重连不再 abort 在飞翻译（只在暂停/结束时 abort）；浮窗在收尾过程中被重新显示时，等收尾结束后自动走恢复流程。

### 仍未处理（需要产品决策或实测）

- 64MB 文档上限与历史归档：当前约 2MB，达到上限前需要确定保留策略（按会话裁剪、拆分大字段或导出分卷），本轮只降低了写放大。
- `store.json` 保存失败后是否再次落盘：取决于 `tauri-plugin-store` 的 `save()` 是否原子写，未实测。
- 输入 token 估算对图片/长 ASCII 的偏差：需要按服务商实测计费口径校准。
- 实时语音旧连接 detach 的所有权、句子乱序重排：属低置信度边界，未改动。

## 备注

截图识别未单独配置视觉模型时会回退到对话模型（`resolveAiRoute` 的 vision → chat 回退）。当前对话模型 `deepseek-flash` 官方支持图片输入，因此模型回复的「截图里没有识别到完整题目，请调整后重试」是对画面内容的判断，不是返回按钮或接口故障。
