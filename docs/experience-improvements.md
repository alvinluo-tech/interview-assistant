# 副屏、记录、存储与模拟面试改进

本轮是本地代码改动，不修改已有发布标签、GitHub 配置或用户的现有数据文件。真实数据迁移在用户运行包含这些改动的桌面版本时执行。

## 副屏控制

- 手机接管时，电脑鼠标在原浮窗映射区域移动，手机显示对应光标；在映射按钮上停留约 1.2 秒触发。手机按钮会显示驻留进度。原有解题快捷键继续可用。
- 原生光标逻辑在交互模式开启、手机光标同步开启时仍执行热区检测。浮窗缩放后重新投射手机热区。
- “切回电脑”恢复电脑浮窗，但保留服务、令牌及连接。手机点“继续副屏”，或电脑副屏卡点“继续副屏”，可再次接管。
- 结束笔试、更换二维码、主动断开连接会使旧配对失效。结束操作保留确认步骤。
- 手机同步整场的所有解题记录，移除只发送最后三题的限制；重置截图不再清空已解题目。

## 笔试记录与截图

每次解题保存识别出的题干、答案、时间和图片引用。题干与答案通过同次视觉请求分区返回，不额外发起一次付费识别请求。模型没有返回独立题干时明确提示，不伪造原题。

截图由现有 Rust `image` 库在后台压缩：保持原分辨率，比较优化 PNG 与质量 92 的 JPEG；透明图片保留 PNG 和透明通道。单张输入/存档上限为 20MB，每题最多六张；保存失败会在记录中显示原因。批次中途失败会移除该批次已写入的附件，不删除已有图片。

历史记录每题提供“查看原图”，支持多图翻页和原尺寸查看。图片按需读取，不把 base64 放进主记录文件，也不发送到手机状态快照。

旧记录中原本没有保存的题干和截图无法补回；已有答案仍保留。模型未按格式返回题干、截图保存失败等情况均有明确提示。

## 历史记录

面试、笔试、模拟面试分为三个入口。模拟面试保留对话与复盘；顶部进度/反馈卡片移除。重命名、删除只修改指定记录，不会因分类过滤而覆盖其他分类。

## 本机存储

使用 Tauri 的系统标准目录，设置中新增“存储”页，可打开对应文件夹：

| 内容 | 位置 |
| --- | --- |
| 记录索引 | AppLocalData / `data/data.json` |
| 原题图片 | AppLocalData / `attachments/exams/<session>/<turn>/` |
| 上一份与手动备份 | AppLocalData / `data/backups/` |
| 可重建缓存 | AppCache |
| 运行日志 | AppLog |
| 设置与受保护密钥 | 沿用原有位置与保护方式 |

首次读取时验证并复制旧版记录，保留源文件；已有新版记录不会被旧文件覆盖。损坏的主记录阻止迁移和覆盖。损坏的旧备份保留原文件、记录日志，但不阻止有效主记录迁移。

手动 JSON 备份只包含记录索引。跨机备份需一并复制记录和附件目录。删除记录后暂时保留附件，避免破坏仍引用图片的备份；本轮不静默删除用户存档。

## 模拟面试与语音

房间采用双人舞台、当前问题、可收起的侧边对话、底部回答区。显示真实会话时长、问题进度、麦克风及播报状态。AI 辅助可以在场内切换。

- 喇叭开关控制面试官朗读，偏好可保留；当前问题可手动重播。
- 配置 TTS 路线时使用该服务，要求兼容 `/audio/speech`；未配置时调用系统语音：Windows 使用 SAPI，macOS 使用系统 `say`，应用代码使用 Rust。
- 静音、开始录音、切换问题、结束会话及关闭窗口会取消旧播报。迟到的云端音频不会开始播放，原生停止操作按请求编号校验。
- 出题、提示及复盘支持取消。结束后丢弃迟到问题；回答保存失败时保留输入，成功保存后出题失败可重试。
- AI 服务设置增加用途概览、系统语音默认选项、语音试听及接口说明。

## 验证

综合发版检查中补充了“开场出题期间刷新记录”的界面回归：旧请求取消后释放其占用，允许替代请求开始；取消旧请求不会释放另一个新请求的占用。

```sh
pnpm test:experience
pnpm test:platform
pnpm build
cargo test --locked --manifest-path src-tauri/Cargo.toml --workspace --lib
node scripts/experience-ui-smoke.mjs
```

界面脚本自行启动独立的 1441 测试服务与新浏览器配置，模拟数据、原生调用和音频，不连接个人账户、不访问真实应用数据，也不实际播放语音。可通过 `UI_TEST_BROWSER` 指定 Chromium 浏览器。截图输出到 `artifacts/mock-room-preview.png`。

自动化覆盖配对保留/恢复、驻留触发、七题历史、原题/答案保存、截图查看、分类重命名隔离、语音路由及取消、结束后丢弃迟到问题、目录迁移与附件压缩。TTS 控制器覆盖率只描述 `questionSpeaker.ts`，不代表整个应用或原生覆盖率。

Windows 原生编译与单元测试通过；真实手机的缩放/DPI/后台重连、系统实际播报、macOS 全应用构建及实机行为仍需设备验收。Mac 的系统语音处理函数已单独进行类型检查，不等同于 Mac 全应用构建或实机验证。
